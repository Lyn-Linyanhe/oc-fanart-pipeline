# 二创流水线初步设定 V0.1

## 状态与范围

这份文件固定已确认方向的初版字段、选择规则和默认值，不是自动化程序使用说明。当前只有旧版 CLI/工作台能生成图片；本轮新增文件没有接入生成器，也没有调用模型或上传图片。

主契约为 `../CONTRACT.md`。本文件细化 V0.1 数据约定；桌面收图手法仍以 `<desktop-library>/搜集方法.md` 为准。旧历史交接中的 MCP/封面/文本限定不能覆盖新契约。

## 角色档案

每个目标角色只建立一份可复用的档案，创作时选择造型，而不是重复找图写设定。

- `appearance`：辨识点、发型、眼睛、体型、默认服装。
- `persona`：性格、背景、关系、动作习惯。
- `emotional_expression`：情绪在眼神、嘴角、手势、身体上如何表现。
- `creation_defaults`：默认保留什么、哪些内容可随本次创作改变。
- `reference_library`：带来源和用途的身份/认可形象/画风参考清单。

设定条目使用 `kind` 区分 `canon_fact`、`interpretation`、`approved_fan_setting`；使用 `verification` 区分 `verified`、`pending`。原作事实也需要出处，不能因模型熟悉角色就标 verified。创作解释不是原作事实，也不是必须遵守的禁令。新增认可形象或二创设定须记录人工确认，不自动把下载图或初审 pass 图升级成身份依据。

参考图记录 `source`、`provenance_status`、`approval`、`views`、`roles`。已有 README 称为官方图但缺原始链接的，标记 `provenance_status: pending`，不伪造来源。

完整参考库覆盖正面、四分之三、侧面、背面、全身、脸部、典型表情；缺图在 `coverage_gaps` 中登记，不为补齐数量编造路径。桌面仍用现有 refs 存放，先不搬素材。

## 参考包选择

一次任务只选一个明确的创作方向，参考包是完整库的子集：

1. 身份参考通常 1～2 张，优先清晰脸部和全身；侧面、背面等按构图需要补充。官方图用于校准，但可使用人工认可形象，不强制每次上传官方图。
2. 画风参考通常 0～1 张，明确借鉴线条、上色、材质、光影、色彩、细节密度；不默认复制其中人物的脸、服装或构图。目标角色图同样可以作画风参考，不因是同角色而直接判无效，但必须说明是否同时承担身份职责。
3. 构图参考选一个完整构图，可以来自别的 IP 或同 IP 其他角色；本角色同人默认不作构图模板，人工明确改变选择时再记录。不妨碍收藏和描述本角色图片，也不妨碍认可形象参考使用。
4. 普通组图按独立构图选取；`split_wide` 的两张保存原序，作为一个不可拆组。正好两张只是候选，未经判断不能当已确认拆分图。
5. 同一文件可承担多个明确职责，在上传清单中去重。优先级为：本次明确创作意图、目标身份辨识约束、指定构图、指定画风；如仍有矛盾，先修订方案，不让模型自行猜。
6. 每个参考记录 `borrow`、`exclude`、`reason`；按身份、画风、构图组织唯一 `upload_manifest`，位置为从 1 开始的连续编号。提示词中的图片编号必须和实际顺序一致。
7. 多图上限、尺寸、质量、输出格式均须按供应商实测能力检查。未验证时 `request_ready` 为 false。无法完整容纳宽图组时阻止提交或明确更换参考，绝不静默丢半张。

当前图片作为软参考，不承诺像 ControlNet 一样锁住布局。画风参考默认可上传；本轮未改变旧实现的 `send_inspire` 开关。

## 参考图预处理（已记录，尚未实施）

用户提出：是否可以先对参考图做预处理，弱化人物形象特征，只保留画风、动作、姿态、神态。

核心矛盾：画风在图像里不是独立通道，笔触、上色、光影与人物结构长在一起，做减法有物理上限。

候选手段与判断：

1. **脸部模糊 / 像素化**（推荐主选）：削弱身份辨识，保留笔触、配色、光影、姿态。风险是模糊块本身可能被当成画面元素画进去。
2. **灰度 / 高对比**：会破坏画风，因为画风大量依赖色彩关系。不建议，除非只要线条风格。
3. **边缘 / 线稿化**：保留构图与姿态，去掉大部分脸部与服装细节。风险是模型把「线稿」本身当风格，输出线稿而非彩图。
4. **裁切 / 遮挡**：直接裁掉或遮住人物头部，最可控，模型看不到脸就不可能抄脸；代价是构图信息有损失。
5. **多图融合**：画风平均化，效果不稳定。

倾向方案：以「脸部模糊」为主、「裁切遮挡」为辅。

关键提醒：这些都是给软参考做预处理。GPT Image 不是 ControlNet，不会严格遵循参考图骨架，预处理只提高概率，不保证结果；真正决定输出的是提示词加图。

更干净的替代路线：先用视觉模型把参考图描述成结构化文字（`vision_screen.py` 已能输出景别、动作、表情、场景、光线色彩），文字本身不含人物身份，用它生成提示词天然不串脸。理想做法是文字描述负责画风与姿态语义、参考图负责具体笔触质感；担心串脸时可只用文字描述。

状态：用户决定暂不实施，仅记录。

## 高清与 4K（已实测：当前线路不支持）

实测结论（2026-10）：上游 `gpt-image-2.5-sunburst` 在当前线路 `image-direct.geiliapi.com/v1` 上**忽略 size 参数**。

- 传 `4096x4096` → 实际返回 1254×1254（耗时约 175s）
- 传 `2048x2048` → 实际返回 1254×1254（耗时约 120s）
- 响应体里的 `width/height` 字段也如实为 `1254x1254`，说明是上游固定输出，不是本地解码问题
- `config.json` 的 `1024x1024` 同样对应这个 1254 输出

因此：**不得宣称支持 2K/4K，也不得把未验证尺寸写进配置**。要真正的更高分辨率，只有两条路：

1. 换一个确实支持更大尺寸的模型或线路，并实测验证。
2. 生成后用图像放大（upscale）处理，属于后处理，不是原生高分辨率生成。

已知画质问题：用户反馈成图有噪点感。这可能与 `quality: medium` 有关（可试 `high`），或与该上游的编码方式有关，尚未定论，待对比测试。

## 工作台结果审核与重新生成（已实现）

工作台主体是「生成结果 · 审核」视图，自动扫描桌面库里已生成的结果图（`我的原创/` 下除 `refs/` 的目录，如 `test5/`、`studio/`），每行左灵感右成图。

- 审核状态：`unreviewed / pass / manual_review / quarantine`，存在 `桌面库/_results/review.json`，重启工作台不丢。垃圾篓是可恢复标记，不移动、不删除原文件。
- 每个结果可从同目录 `run_log.jsonl` 回读生成参数（`shot/pose/style/inspire`）。工作台新生成的图会自动追加该日志。
- 「重新生成」按钮把原参数填回生成区，改完提交即产出新图，作为独立一行出现，原图保留；`run_log` 里用 `redo_of` 记录来源。
- 生成时间早于日志功能的图没有参数记录，重做时只能带出部分信息，界面会明确提示，不会假装参数完整。

已知限制：当前一次请求仍是「一张身份图 + 可选一张参考图」的旧结构，画风参考没有独立的职责说明，因此「连灵感图一起送」并不保证画风迁移。参考包分层见上文设计方向，尚未接入。

## 视觉筛图模块（已实现，独立于生图）

`scripts/vision_screen.py` 已实现筛图与结构化描述，使用独立的 `~/.zcode/oc-fanart-vision.local.json`，与 `image-edit.local.json` 的生图 profile 完全分开；不会调用 `/images/*`。

```text
python scripts/vision_screen.py --dir <构图库目录> [--limit-groups N] [--limit-images N] [--dry-run]
```

- `--dir` 含子目录时，每个子目录当作一篇笔记；扁平目录下每张图各自成组。未接入新「笔记文件夹」布局前，扁平旧库按单图处理是预期行为。
- 结果写到 `<dir>/_vision/<note_id>.json`，结构见 `templates/image-description.json`。
- 每张图输出 `usable/contains_person/character_count/shot/action/expression/scene/lighting_and_palette/decorations/visible_facts/interpretations`；`visible_facts` 与 `interpretations` 分开。
- 正好两张一组时，额外调用一次判断 `split_wide`，返回 `is_split_wide/confidence/reason/left_contains_person/right_contains_person/combined_composition`。独立情头、上下分格漫画会判为非宽图对。
- 已成功解析的图会缓存命中，重跑只补失败或缺的图，不重复计费；HTTP 错误不重试，只有网络层失败按 `--retries` 有限重试。
- 实测：`gpt-6-luna` 单图约 1400–1500 token；首次 TLS 握手可能超时，属网络层瞬时失败，可安全重跑。
- 本模块只上传构图库图片，不上传 `characters/*/refs/` 身份图。

当前限制：`split_wide` 只在组内正好两张时判断；更精确的宽图识别依赖后续接入「一篇笔记一个文件夹」的收图布局和 `note.json`。

## 筛图与轻量描述

便宜视觉模型候选为用户指定的 `gpt-6-luna` / `deepseekv4.1`，实际模型 ID、看图能力和价格待验证。抓取和下载等确定性工作用脚本，视觉筛选与描述可一次 API 请求完成，不需要 agent。

筛选值 `keep/reject/manual_review` 只代表库素材状态，不与生成审核或请求执行状态混用。检查有没有人物、是否纯文字、清晰度、完整构图。宽图组按整体判断，单半张没有人物不能直接剔除。reject 图保留原文件，待人工复核。

描述默认中文、简短结构化，不要求长提示词。人物识别可留 null；心理解释放 `interpretations`，不能写成 `visible_facts`。一篇笔记有五个独立构图就可以有五份描述；描述数量不等于生成数量。

不同构图组可并行。搜索仍一个登录窗口。并发、缓存、超时策略后续实现，不在此虚设实际已可用的吞吐量。

## 画面设计与提示词

输入角色档案、选定参考包、描述和创作意图，输出模块化画面设计和完整提示词。模块包括身份、情绪可见表达、动作/形态、镜头/布局、场景光色、画风/材质、装饰、限制。不是把描述逐条机械拼接。

本次 `allowed_changes` 可以明确允许换服装、发型、夸张表情或反差人设；模板不能把这些一概禁止。明确心理情境要转成可画的线索。装饰文字区分是否需要、具体内容、位置，不默认搬运灵感图的署名/水印。

模板先从实际出图验证有效表达，再沉淀可复用模块。画面设计输出的 prompt 在能力与预算检查通过前不直接执行。

## 初审、修订和垃圾篓

模型初审同时看新图、参考包、初始提示词及明确创作意图。审核结论为 `pass/revise/manual_review/quarantine`；问题记录类型、可见依据、严重程度和建议，不用未经校准的总分替代判断。

- pass：符合初筛要求，不等于人工认可身份参考或最终满意。
- revise：存在具体可改问题，且下一次请求预算已获授权。
- manual_review：不确定或需人判断，暂停自动生成。
- quarantine：明显不合适、不可修或修订耗尽，标记进可恢复垃圾篓。

垃圾篓初版设定为版本标记 `storage_state: quarantine`，不移动、不直接删除文件，恢复时改回 active 并留操作记录；实际 UI 尚未实现。

修订先重看提示词和参考包，记录需要改的模块、参考、参数与原因，再产生子版本。V0.1 默认最多自动修订 1 轮，人工显式加额度才能继续。修订图片已成功返回但不合适，是新创作版本；超时/5xx/内容策略导致请求失败，不允许自动重试或伪装成自动修订。

`execution.status` 为 `not_submitted/queued/running/succeeded/failed/unknown`，独立于审核状态。超时且无法确认是否扣费用 unknown，先对账，不自动提交另一次。

## 版本与费用边界

实际版本 ID 使用唯一值（例如 UUID），不能只靠秒级时间或重复任务名。同一 `work_id` 下记录 `parent_version_id`，保留图片、角色档案快照、提示词、参数、参考顺序、模型名、审查和人工操作。修改后的任务不覆盖旧图。

运行前必须明确：初稿数量、自动修订额度、允许的最大生图请求数、费用上限及人工认可。费用未知时先单次测试并明确授权，不能推定预算。垃圾篓图仍计费。独立文本/视觉处理的并行不代表允许生图无限并行。

## 草稿、高清与工作台

已跑通兼容基线为 `gpt-image-2.5-sunburst`、`1024x1024`、`medium`，不宣称最低成本。更低质量/更小尺寸需确认供应商支持和实际效果。4K 目标不等于已支持 `4096x4096`；高清预设尺寸暂为 null。

人工挑中后，以选中图为基础做放大或编辑，记录保留构图、表情及局部细节的要求；不默认另起随机构图。高清是子版本，结果仍要审核。

工作台以后支持模型/尺寸/质量/格式切换、草稿/高清预设、参考角色标签、完整参考清单、手改提示词、版本、审核和恢复。优先逐行左右对比，不回退成仅灯箱浏览。局部修图、比较和快捷操作用于加速人机精修，具体交互尚未实现；不更改或耦合 8765 画布。
